## Purpose

Convert the approved layout invariant patch into an implementation-safe rollout sequence that protects Orbit’s core principle:

- canvas = user territory,
- system strip/chrome = Orbit territory,
- no in-canvas system intrusion.

This plan is intentionally ordered to de-risk coordinate continuity before deeper Hide+Snooze+Resurface work.

---

## Assumed starting point

- Foundational layout invariant spec is approved.
- Existing hidden/lens/card behaviors are live and must not regress.
- Coordinate model risk is the primary technical uncertainty.

---

## Rollout packets / slices

## Packet 0 — Baseline audit and observability gate (pre-change)

**Goal:** establish confidence baseline before touching layout shell.

**Scope**
- Snapshot current behavior at representative viewport sizes and zoom levels.
- Instrument/log effective layout bounds and card coordinate reads/writes.
- Confirm where current system chrome touches/overlaps card area.

**Why this packet exists**
- Prevents “we think we fixed it” outcomes without measurable before/after proof.
- Creates rollback reference artifacts.

**Exit artifacts**
- Baseline overlap matrix (size/zoom).
- Coordinate write/read trace sample.

---

## Packet 1 — `canvasViewportRect` contract and shell split

**Goal:** create enforceable layout boundary as first-class contract.

**Scope**
- Introduce canonical `canvasViewportRect` generated by shell.
- Refactor layout composition into explicit regions:
  - system strip region,
  - canvas viewport region.
- Ensure all system-layer placement APIs consume boundary guard.

**Why this packet exists**
- Without first-class boundary, future features will regress by convenience.

**Exit condition**
- Boundary exists, is queryable, and can be asserted in tests.

---

## Packet 2 — Chrome relocation + strip pressure behavior

**Goal:** move all system chrome outside canvas and harden strip behavior under pressure.

**Scope**
- Relocate context/hidden/lens controls and system acknowledgments outside canvas.
- Enforce strip priority:
  1) Context
  2) Hidden
  3) Lens
  4) Resurface acknowledgment
- Implement ack degradation chain: full text → compact token → disappear.
- Responsive reflow/collapse rules that never cross canvas boundary.

**Why this packet exists**
- Produces visible product payoff early while preserving invariant discipline.

**Exit condition**
- No system chrome in `canvasViewportRect` across supported viewport/zoom matrix.

---

## Packet 3 — Coordinate semantics gate + migration (conditional)

**Goal:** eliminate coordinate continuity risk before shipping invariant broadly.

**Scope**
- Determine persisted coordinate model:
  - canvas-relative (preferred), or
  - absolute-display (migration required).
- If absolute-display: implement one-time normalization migration to canvas-space.
- Validate no card-jump continuity break across restart/update.

**Why this packet exists**
- Layout shell changes can silently break user trust if cards shift.

**Exit condition**
- Coordinate model explicitly confirmed; migration shipped and validated if required.

---

## Packet 4 — Non-destructive behavior hardening

**Goal:** lock invariant behavior under real interactions.

**Scope**
- Verify no system event mutates existing card coordinates.
- Verify drag/hide/unhide/lens remain stable while strip state changes.
- Validate deterministic insertion policy scaffolding for future resurface:
  - prior coordinates if collision-safe,
  - deterministic fallback,
  - never displace existing cards.

**Why this packet exists**
- Makes the foundation “feature-ready” for snooze/resurface without hidden layout debt.

**Exit condition**
- Non-destructive guarantee proven in regression matrix.

---

## Packet 5 — Foundation release checkpoint

**Goal:** declare layout invariant foundation ready for Hide+Snooze+Resurface spec/build.

**Scope**
- Final regression sweep.
- Explicit sign-off that no in-canvas system lanes remain.
- Freeze invariant as a reusable product rule for subsequent features.

**Exit condition**
- Foundation accepted; deeper Hide+Snooze+Resurface can proceed safely.

## Sequencing and dependency gates

## Required sequence
1. Packet 0 (baseline)  
2. Packet 1 (boundary contract)  
3. Packet 2 (chrome relocation/pressure behavior)  
4. Packet 3 (coordinate gate + migration if needed)  
5. Packet 4 (non-destructive hardening)  
6. Packet 5 (foundation checkpoint)

## Hard gates
- **Gate A (after Packet 1):** `canvasViewportRect` is authoritative and test-visible.
- **Gate B (after Packet 2):** zero system chrome overlap at supported viewport/zoom matrix.
- **Gate C (after Packet 3):** coordinate model confirmed; migration validated if triggered.
- **Gate D (after Packet 4):** no system-driven coordinate mutation outside explicit user move or deterministic resurfacing insertion rule.
- **Gate E (after Packet 5):** foundation sign-off before Hide+Snooze+Resurface feature-layer implementation.

## Parallelizable work
- Copy/design tuning of strip labels and compact token visuals can run in parallel with Packet 2 implementation.
- Test harness expansion can begin during Packet 1, but final assertions depend on Packet 2 boundary behavior.

## Must wait
- Hide+Snooze+Resurface interaction implementation must wait until Gate C at minimum (prefer Gate E for full safety).

## Key risks and rollback guidance

## Risk 1 — Coordinate model mismatch (highest)
**Failure mode:** persisted absolute-display coordinates interpreted as canvas-relative (or vice versa), causing card jumps.

**Mitigation**
- Mandatory model audit before enforcement.
- Conditional migration with replay testing on real saved data samples.

**Rollback guidance**
- Feature-flag invariant enforcement by shell region.
- If continuity regression appears, disable strict enforcement and revert to pre-patch layout shell while preserving migrated data snapshot.
- Keep migration idempotent + reversible mapping logs for one rollback window.

---

## Risk 2 — Responsive strip overflow drives accidental canvas intrusion
**Failure mode:** narrow widths or zoom force controls into canvas.

**Mitigation**
- Predefined pressure policy (priority + ack degradation) implemented before release.
- Multi-size/zoom non-overlap tests as release gate.

**Rollback guidance**
- Disable lowest-priority strip element rendering (ack first) before allowing any overlap.
- Fall back to compact strip mode globally under pressure.

---

## Risk 3 — Interaction regressions from shell refactor
**Failure mode:** drag jitter, hidden tray oddities, lens toggles desync.

**Mitigation**
- Preserve interaction ownership boundaries while relocating chrome.
- Regression pass focused on drag/hide/unhide/lens transitions.

**Rollback guidance**
- Revert shell composition changes as one unit (not piecemeal component rollback).
- Keep packet commits separable so Packet 2 can roll back independently from Packet 1 contract scaffolding.

---

## Risk 4 — Deterministic placement not truly deterministic
**Failure mode:** resurfacing fallback appears random or displaces cards.

**Mitigation**
- Define deterministic collision-safe fallback rule before using it in feature layer.
- Add repeated-run determinism checks.

**Rollback guidance**
- Temporarily limit resurfacing insertion to prior-coordinates-only when safe; otherwise hold hidden state and surface informational acknowledgment in strip.

---

## Implementation-safe ordering before Hide+Snooze+Resurface

Practical safe order:
1. Ship boundary contract + test hooks (Packet 1).
2. Ship chrome relocation + pressure behavior (Packet 2).
3. Resolve coordinate model/migration risk completely (Packet 3).
4. Harden non-destructive guarantees (Packet 4).
5. Only then begin Hide+Snooze+Resurface feature-layer implementation.

This avoids building snooze/resurface on unstable layout or uncertain coordinate semantics.
